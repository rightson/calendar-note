PRODUCT PROPOSAL · UPDATED 2026.10.23 · DRAFT

Plan your time.
Keep the story in your notes.

Calendar-Note is an Obsidian calendar built around Event Notes. Create, overlap, and reschedule local events without iCal. See the current week at a glance, click a week number to write in its Weekly Note, click a date to open its Daily Note, or click an event to open its Event Note and add a link to the Daily Note for that event's date.

User story and V1 scope

As an Obsidian user, you want to plan local events in a weekly calendar and optionally subscribe to external calendars. When an iCal event's date or time changes upstream, you want the calendar and its linked notes to follow that change automatically, then review what changed and resolve any local override or write conflict. Clicking an event should open its note and create an entry in the correct Daily Note. Rescheduling must preserve the same Event Note. You also want to recognize the current week immediately, click week numbers to open and edit Weekly Notes using your existing Calendar plugin folder and format, and open Daily Notes even on dates without events.

Readable week navigation and date notes

Week numbers are entry points for writing, not just labels. Keep the current week easy to spot with a subtle highlight on its week number, even while browsing another period. The highlighted sidebar number remains clickable and opens that week's Weekly Note. Place a compact Today control beside mini-calendar month navigation; do not add a separate current-week call-to-action or a standalone week/range row. Week numbers are computed from dates; clicking a number opens the note rather than editing the number itself.

  • Sidebar and month: Pair the Today control with month navigation. Use a clean, single-number week gutter, with a subtle divider before the seven date columns and a subtle current-week highlight that remains clickable. Avoid per-row year labels, tiny stacked text, and touching weekday names. Give the sidebar enough width for separate cells and readable text; compact weekday headings retain full accessible names.
  • Calendar views: Keep week-number gutters clickable wherever the calendar presents them. Do not insert a separate week/range row above the main calendar; use the week numbers already shown in the view.
  • Week identity: Accessible week-button names, tooltips, and the opened note panel include the full week-year and date range. Handle rows that cross months or calendar years using the effective week convention. Enter and Space activate week buttons, and closing the note returns focus to its entry point when available.
  • Main calendar dates: Week/day date headings, month dates, and every list date heading open their Daily Note while retaining the view. List view includes empty dates. Sidebar date buttons remain calendar navigation, and Today and previous/next continue to navigate.
  • Calendar chrome: Use English abbreviated labels regardless of note locale, keep main date headers on one line (for example, Sun 18), and show adjacent mini-calendar months when sidebar height permits. Date formatting and week identity continue to use provider locale and week rules.
  • Sidebar and day filtering: Persist the sidebar width and collapsed state; allow pointer/keyboard resizing. Close the expanded sidebar with its × control and restore it with a compact left-edge icon handle that uses no toolbar row. Bottom-align sidebar and main calendar and fill available pane height. Workdays filters Monday through Friday in the main calendar only; All days is the default, and the mini-calendar remains seven days. Confirm toggling modes does not duplicate the mode header.
  • Open calendar: In a disposable test Vault, confirm a ribbon click opens a new tab and Ctrl/Cmd-click opens a right split beside the active leaf. Run open-calendar and open-calendar-right from the command palette and confirm both are available in Obsidian Hotkeys for user-assigned bindings. Do not expect default bindings.
  • Event Note display and titles: Confirm Follow Obsidian leaves the native Properties state unchanged, Collapsed is the default initial state, Expanded reopens expanded, and manual toggles remain available. Verify ordinary notes are unaffected. On an active recognized Event Note (nonblank event_id and valid start/end), run Remove duplicate Event Note title; remove only an exact matching leading H1, preserve frontmatter and remaining body, and make a second run a no-op. Never migrate notes automatically.

Weekly Notes and Calendar compatibility

The plugin resolves weekly settings using the same provider precedence as Calendar: enabled Periodic Notes weekly settings take precedence; otherwise use Calendar's weeklyNoteFormat, weeklyNoteFolder, and weeklyNoteTemplate. If neither provider is available, use Calendar-Note's own settings. An installed provider's blank folder means the Vault root; do not replace it with a fallback folder. Blank format uses gggg-[W]ww. Read settings without changing another plugin's configuration, and show which provider is active.

Calendar uses Moment locale weeks, including its effective locale override and first-day setting. Lowercase gggg/ww are locale week-year/week tokens; uppercase GGGG/WW are ISO tokens. Preserve their actual meaning instead of silently rewriting formats. Calendar's first-day override changes the locale's first weekday while retaining its first-week rule. With English (US) and locale-default weeks, January 1, 2027 is week 1 of 2027; ISO weeks place it in week 53 of 2026. English (UK) locale weeks follow Monday/January-4 rules. Do not infer a week-year from calendar-year YYYY.

The plugin retains provider locale and week rules for date formatting and week identity. Calendar chrome uses English abbreviations regardless of note locale. ISO mode uses Monday and the January-4 rule. Calendar-Note fallback defaults are folder Weekly Notes and format gggg-[W]ww; the folder is literal text and format is Moment syntax. Resolve the format at the selected week's start in the configured display zone, so all days in that week open one path. Do not expand Moment tokens in the folder value. Native editor QA opened Weekly Notes/2026-W43.md, confirmed autosave, and confirmed the edited text survives plugin reload. The final native Week-label and Month/Year date controls were also checked; sidebar week-number activation and provider precedence remain to be exercised in the test-Vault checklist.

Formats intentionally sharing a path reuse the same weekly file; do not invent suffixes. Changing weekly settings changes future resolution without moving or erasing existing notes. No iCal setup is required for any note entry point.

Daily Note entry points

Opening a date resolves the Daily Note from that calendar date in the display time zone, independently of event visibility or subscriptions. Reuse core Daily Notes folder, format, and template when enabled, or Calendar-Note's fallback settings otherwise. Open existing content unchanged, or create a missing file from its template. Clicking a date creates no Event Note or event bullet.

Daily Note formats use date tokens and literal text without event variables. Both date and event entry points resolve at the corresponding day's midnight. In the plugin, a new fallback Daily Note begins with ## Journal and no generated H1; the prototype instead uses its own saved format and locale, fixed to Asia/Taipei, and starts with a date heading and Journal section. Existing notes and user templates are preserved without automatic heading changes. The direct prototype panel remains read-only with Markdown download. Repeated clicks and shared custom paths preserve content. Dates outside the displayed month follow the same rules.

Compatibility references: Calendar settings, weekly opening, effective locale/week rules, and settings-provider precedence. References establish the design contract; no integration is running in this prototype.

Daily Notes integration

Use the event's effective start date in the display time zone, rather than the date of the click. For example, clicking an October 22 event on October 23 must update Daily Notes/2026-10-22.md. All-day events retain their original date without a time-zone conversion that shifts the day.

  1. For an event click, ensure that the Event Note exists before resolving the Daily Note. When core Daily Notes is enabled, reuse its folder, custom format, and template. Create missing folders and journal files.
  2. When core Daily Notes is disabled, use Calendar-Note's Daily Note path setting, defaulting to [Daily Notes]/YYYY-MM-DD. Other plugins are not prerequisites.
  3. Find ## Event. If absent, append that section to the body. If present, append the bullet within it, before the next heading at the same or a higher level. Preserve existing text and other sections.
  4. The bullet links to the Event Note and includes the event time. Reopening the same event updates the same entry. Different events retain separate links even when their titles match.
  5. If the start date changes, move only the entry managed by Calendar-Note to the new date. Changes within the same day update its time. Do not remove unrelated text, handwritten bullets, or Event Note content.

Compact frontmatter and stable identity

Local events normally need only event_id, start, and end. Add all_day: true for all-day events. Use ISO timestamps with offsets. Let users choose whether Event Note Properties follow Obsidian, open collapsed (default), or open expanded. Apply this choice as the initial display state when a recognized Event Note opens, then allow manual toggling. Keep the properties readable and exportable in Markdown.

Imported events add only necessary source references. source identifies the subscription and UID; recurring events also retain the original recurrence_id. Keep full provider data in the subscription cache instead of duplicating it in every note. Preserve user-defined properties when updating managed fields.

Use subscriptionId + UID for single imported events and subscriptionId + UID + original occurrence start / RECURRENCE-ID for recurring occurrences. Local events use an immutable event_id. The effective start time is editable and must not become a mutable identity. Changing times, titles, or note filenames must still open the same note.

When a user edits times in Event Note frontmatter, reparse and validate the interval before updating the calendar. Invalid intervals show an error instead of creating new events. Daily Notes are an index; handwritten bullets are not parsed as a second event source.

Imported event changes and review history

Match imported events by stable source identity: subscriptionId + UID for a single event and subscriptionId + UID + original RECURRENCE-ID for a recurring occurrence. The effective start time may move while the recurring identity keeps the original occurrence anchor; never match by title or revised date. This follows iCalendar's UID and RECURRENCE-ID semantics in RFC 5545 §3.8.4.7 and §3.8.4.4.

On a successful source refresh, update the calendar event, the linked Event Note's managed start/end frontmatter, and its Daily Note entry. Keep the Event Note path and body. Rewrite or relocate only the tracked Daily Note bullet to the revised start date, preserving the journal and unrelated content. If an imported event has no linked note yet, update the source cache and history without creating an Event Note or Daily Note on each poll. The prototype exposes this flow through an explicit Simulate iCal change action using parsed fixtures; it does not fetch an ICS URL.

Keep a persistent change-history row for each distinct detected revision. Record detection time, calendar friendly name, stable event key and title, source old/new ranges, effective old/new ranges, outcome (Applied automatically, Kept local time, or Needs attention), result Event Note path, Daily Note path before/after, and any error. Do not store private subscription URLs or ICS payloads in the history. Show an unreviewed count, All and Needs review filters, and actions to open the note and mark a row reviewed. Mark reviewed acknowledges the row; it does not approve, apply, revert, or erase the recorded change. Offer Retry only while the accepted source still matches the baseline of the failed revision. A redacted JSON export is not required.

Identical event times create no new history row. When accepted source revision metadata such as SEQUENCE advances without a time change, update the accepted source baseline without a history row or note-artifact write; reject older metadata as stale. A detected transition A→B and a later B→A are two distinct history rows; establishing the initial baseline creates none. Any newer accepted revision supersedes pending failed work, even if later accepted revisions return the event to its original times (A→C→A). A subsequent A→B change is a new revision with a distinct history row; do not resurrect or reuse the earlier failed row. With a local time override, keep the local effective time and record the upstream source change explicitly, without labeling the source time as applied. Use latest source times clears only the time override, applies the latest source interval to the event and its linked artifacts, and records that resolution in history.

All related writes must succeed together. A failed write, pattern collision, or rewritten managed bullet leaves the last committed calendar event and note artifacts intact, records a retryable needs attention result, and does not duplicate a pending revision. The browser prototype simulates this as one local-storage transaction. The plugin implementation includes a durable transaction journal and serializes writes per file. Browser simulation does not establish Vault recovery behavior; confirm that behavior in a disposable test Vault.

If a tracked bullet in a past Daily Note was edited or moved and cannot be safely rewritten, request relinking instead of guessing. A changed UID or ambiguous recurring occurrence mapping needs review and must never overwrite a possibly unrelated note. Distinguish cancellation, invalid feeds, and events outside the visible range from an event that is still present; never automatically delete existing notes or journal entries for these states.

  4. Resolve occupied filenames as Title (2).md without overwriting unrelated files. Reopen the original path for the same event. Use event locks, case folding, and Unicode normalization to avoid duplicate creation.

Acceptance criteria

  • No iCal: With all URLs cleared, create local events, Event Notes, and Daily Notes; open and edit Weekly Notes; edit event times; and reload persisted data.
  • Week readability: The current week is obvious without hover. Sidebar weekday names and numbers never touch or wrap; each row shows one week number. Desktop and narrow-screen checks cover visible/hidden sidebar layouts, browser zoom, and cross-year rows.
  • Weekly entry points: Click or keyboard-activate the current-week-highlighted and other sidebar/month week numbers. Open the matching Weekly Note, edit Markdown, switch notes, reopen, and reload without losing edits. Weekly actions create no event or Daily Note artifacts.
  • Week conventions: Calendar / English (US) puts January 1, 2027 in 2027-W01; ISO puts it in 2026-W53. English (UK), Sunday/Monday overrides, and uppercase/lowercase Moment tokens retain their actual semantics. Every date within a selected week resolves to the same weekly file.
  • Weekly paths: Match configured Weekly note format and Weekly note folder, including empty root folder, default format, literals, nested date folders, and shared files. Protect Event/Daily/Weekly content from path collisions. The plugin implements Calendar/Periodic provider precedence and templates; verify provider detection in a test Vault.
  • Date entry points: Activate week/day date headings, month dates (including adjacent-month dates), and every list date heading by mouse or keyboard. Open that date's Daily Note and retain the view. Day view follows the selected date; sidebar date buttons still navigate.
  • Dates without events: With no events, no subscriptions, or all sources hidden, every main date remains usable. Opening a date creates only a missing Daily Note, adds no Event section or event link, and leaves Event Notes and events unchanged.
  • Direct Daily Note preservation: Reopening, reloading, and opening through an event all reuse the resolved Daily Note. Preserve existing Markdown, event links, and shared-path content. Use the saved Daily Note format and locale with a midnight date anchor; different events on one date resolve to the same file as a date click. Reject event placeholders, invalid paths, or Event Note collisions without overwriting files.
  • Past events: Clicking an October 22 event on October 23 adds a link only to the October 22 Daily Note's Event section.
  • Journal preservation: Create missing journals/sections; append without replacing existing bullets or following sections. Reopening an event leaves one entry.
  • Creation entry points: Empty slots prefill the correct time. Right-clicking a covered slot can create a second or third event.
  • Overlap: Three overlapping events remain distinguishable, clickable, and editable. Touching intervals do not count as overlap.
  • Both resize edges: The top changes only start; the bottom changes only end. Enforce 15 minutes, restore canceled/invalid operations, and avoid accidental creation.
  • Frontmatter: Local events need three fields. Time edits preserve body text, unrelated properties, and note paths.
  • Stable links: Time changes reopen the same note, update the existing bullet, and move it when the start date changes.
  • Separate paths: Event Notes support date and event variables. Daily Notes follow the core custom format or independently configured fallback.
  • Safe filenames: Handle slashes, colons, reserved names, empty titles, and long Unicode/emoji text. Different events never overwrite each other's files.
  • iCal reliability: Source failures do not block other sources or local features. Rescheduling imported events stores local overrides without upstream writes.
  • Source identity: A single imported event matches by source and UID; a recurring occurrence matches by source, UID, and its original RECURRENCE-ID even when DTSTART changes. Never infer a match from title or revised date. Changed UIDs and ambiguous occurrence mappings require review and cannot overwrite an unrelated note.
  • Automatic source changes: After a successful refresh, update the calendar, managed Event Note start/end, and the tracked Daily Note bullet while preserving the same Event Note path/body and all unrelated journal content. Relocate the bullet when the event's start date changes. An unlinked import updates only cache/history until a user opens it.
  • Change history: Record detection time, calendar name, stable key/title, source and effective old/new ranges, outcome, Event Note path, Daily Note path before/after, and errors. Show unreviewed count and All/Needs review filters; Open note and Mark reviewed work, with marking limited to acknowledgment. Retry only while the accepted source matches the failed revision baseline. A superseded failed row leaves Needs review and decrements the unreviewed count after acknowledgment, but stays in All. Keep private source URLs and ICS data out of history. Identical event times add no row; accepting newer source revision metadata with unchanged times updates only the baseline; A→C→A supersedes earlier pending work, and a later A→B revision receives a distinct history row; initial baseline adds none.
  • Overrides and resolution: A source change while a local override exists keeps local effective times and records that outcome. Use latest source times clears only the time override, updates linked artifacts, and records the resolution.
  • Write safety and recovery: A failed file write, path collision, or changed managed bullet leaves committed calendar and note artifacts unchanged. Persist a retryable needs-attention item without duplicating a pending revision. The plugin uses a durable recovery journal and per-file lock; the browser preview covers only a local-storage transaction.
  • Removed or uncertain events: Distinguish cancellation, invalid feed, and event outside the visible range. Keep existing notes and entries. When a tracked past bullet cannot be safely rewritten, ask the user to relink rather than guessing.
  • Complete plugin: Validate recurrence exceptions, DST, midnight crossings, exclusive all-day end dates, manual note moves, and file-write failures separately.
