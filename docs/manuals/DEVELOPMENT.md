# Calendar-Note development and QA

Calendar-Note 0.1.0 targets desktop Obsidian 1.14.5 and later. Desktop-only describes the verified release scope; mobile behavior has not been tested. The native QA below was performed in an isolated Obsidian 1.14.5 Vault. Automated tests cover core logic through adapters and fixtures, so they do not establish every native UI behavior. See the [0.1.0 release notes](../releases/0.1.0.md) for a concise public summary and [releasing](RELEASING.md) for packaging and release steps.

Calendar-Note now has a local Obsidian plugin implementation. The HTML pages under `docs/changes/calendar-note/preview/` remain a separate browser prototype: they use browser storage and fictional sample feeds, and do not inspect or modify a Vault.

## Build and package

Requirements: Node.js 22 or newer, npm, and `zip` for packaging.

```sh
npm ci
npm run typecheck
npm test
npm run build
npm run package
```

`npm run build` writes the plugin bundle to the repository root as `main.js`. `npm run package` rebuilds it and creates `dist/calendar-note.zip`, containing the `calendar-note/` directory with `main.js`, `manifest.json`, `styles.css`, `LICENSE`, and generated `THIRD_PARTY_LICENSES.txt`.

For a dedicated test Vault, build first and use an explicit absolute path:

```sh
npm run install:test-vault -- /absolute/path/to/calendar-note-test-vault
```

The installer requires an existing directory with `test` in its name and writes to that Vault's `.obsidian/plugins/calendar-note/`. It will not install to the repository or a directory without `test` in its name. To install manually, extract the archive's `calendar-note/` folder into `<TEST_VAULT>/.obsidian/plugins/`. In Obsidian enable community plugins and Calendar-Note under **Settings → Community plugins**, then reload if prompted.

Uninstall by disabling Calendar-Note and removing its plugin folder. `data.json` inside that folder stores plugin settings, source/cache/history, and note-link tracking; `recovery.json` stores any interrupted multi-file transaction. Removing the folder removes both files. Event, Daily, and Weekly Markdown files and their existing links remain in the Vault. Copy `data.json` first if you may want to preserve settings, history, or tracking state. Resolve pending recovery before uninstalling; if it cannot be resolved, keep a copy of `recovery.json` until recovery is handled. The plugin has no automatic Vault-note cleanup command.

## Plugin behavior and boundaries

The plugin registers a Calendar-Note view with Week, Day, Month, Year, Custom days, and List views. Clicking the ribbon icon opens the calendar in a new tab; Ctrl/Cmd-click opens it in a right split beside the active leaf. These actions are also available as the `open-calendar` (“Open calendar in new tab”) and `open-calendar-right` (“Open calendar in right split”) commands. Obsidian registers both commands for user-assigned hotkeys; the plugin adds no default bindings. The toolbar toggles the main calendar between All days (the default) and Workdays (Monday through Friday); the mini-calendar always retains seven days, and the setting does not change note week rules. The sidebar has a Today control beside month navigation and a keyboard-accessible resize separator. Close the expanded sidebar with its ×; a compact, keyboard-focusable icon handle at the left edge restores it when collapsed without consuming a toolbar row. Native checks confirmed the handle is accessible and restores the saved width. The main calendar can be hidden the same way with the toolbar's panel icon, and a matching handle at the right edge restores it. With the main calendar hidden, the mini calendar fills the view in as many month columns as fit; clicking a date opens its Daily Note, and a week number its Weekly Note, in a split to the right of the calendar, reusing that split while it stays open. Hiding one panel always shows the other, so the view is never empty. This mode has automated coverage only; it has not had native QA. Sidebar width and both collapsed states are stored in plugin settings. Other commands are `new-event`, `refresh`, `change-history`, `retry-recovery`, and `remove-duplicate-event-note-title` under the `Calendar-Note:` display prefix. Local event files use `event_id`, `start`, and `end` frontmatter; imported notes also track source identity and recurrence ID. Event Note body content and unrelated frontmatter are retained when managed fields change. The event details dialog's **Change…** control links an event to another Markdown note, or to a new note at a typed path. The chosen note gains the managed fields and its own heading or filename becomes the event title; the previous Event Note loses only the managed fields; the Daily entry is rewritten to the new link in the same transaction. A note that is already another event's Event Note, a Daily Note, has invalid YAML, or already uses a managed property name (`event_id`, `start`, `end`, `all_day`, `source`, `ical_uid`, `recurrence_id`) is refused unchanged. This control has automated coverage only; it has not had native QA. Event Notes link to a managed bullet under the Daily Note's `## Events` section (an existing `## Event` section is still used). A bullet is identified by its generated form and its link to the Event Note, so a stale time or alias is rewritten in place and repeats are removed; lines in the user's own words are never changed. Opening, creating, moving, or saving an event adds its entry back when none remains, while a background source update leaves a rewritten or removed entry alone and records a change that needs attention. The event-title input uses a vertically labeled, full-width row.

Date patterns use Moment formatting and the configured IANA display zone (default `Asia/Taipei`). Daily Notes follow enabled core Daily Notes settings, then Calendar-Note fallback settings. Weekly Notes prefer enabled Periodic Notes weekly configuration, then Calendar plugin weekly configuration, then Calendar-Note fallback settings. Detection uses internal Obsidian provider state because there is no public provider API; provider upgrades may change those internals. Templates are Vault-relative Markdown paths with `{{date}}` and optional `{{date:FORMAT}}` replacement. Event Note patterns additionally accept `{title}`, `{calendar}`, and `{uid}`. The Event Note Properties setting offers Follow Obsidian, Collapsed (default), and Expanded, applied as the initial display state when a recognized Event Note opens. Users can toggle Properties afterward. The implementation depends on Obsidian's editor DOM/CSS behavior; it does nothing when the native property panel is unavailable or hidden, and may need adjustment if Obsidian changes its selectors.

Subscriptions accept HTTPS and `webcal://` feeds. The plugin converts `webcal://` to HTTPS, uses conditional requests when available, parses feeds with `ical.js`, caches the response privately, and does not write to the upstream calendar. A UTF-8 BOM before `BEGIN:VCALENDAR` is accepted. Timed events without `DTEND` or `DURATION` are retained as zero-duration events; short source intervals are also retained. The 15-minute minimum applies to local creation and manual editing or rescheduling of any event, including imported events. Recurrence instances are identified by source, UID, and original RECURRENCE-ID. Imported event rescheduling is local-only. Source changes can update managed Event Note times and the tracked Daily Note bullet, while preserving note body and unrelated journal content. History tracks accepted changes and supports review, eligible retry, and explicit resolution of local overrides. A durable recovery journal preserves prior committed state and pauses edits when interrupted writes require recovery. There is no automatic deletion of notes when events are cancelled or removed from feeds.

### Subscription troubleshooting

An ICS URL can work in iOS and fail here because clients may support different valid iCalendar forms. Before the current parser updates, feeds containing multiple complete `VCALENDAR` streams and `RDATE;VALUE=PERIOD` recurrence values exposed compatibility gaps. Automated parser fixtures now cover these forms; native UI rendering has not been verified for the new parser changes. Delta objects sent with `METHOD:CANCEL` are unsupported, whether or not they include event times. They should report a specific error rather than be applied as a full subscription snapshot that could remove unrelated imported events. This does not change handling of `STATUS:CANCELLED` inside a complete snapshot. The specific feed reported by the user was not provided, so its contents and provider behavior have not been inspected and these known pre-fix gaps are possible causes, not a diagnosis.

Use the source's displayed diagnostic category to narrow down the problem: body or syntax errors indicate the response could not be parsed as iCalendar; semantic UID, time, range, limit, or timezone errors indicate parsed data failed validation; network and HTTP errors report request failures; empty and `304` cache outcomes describe feeds without importable events or unchanged cached content; write errors indicate local sync/storage failure. A write failure should not be reported as invalid ICS. When reporting an issue, share the diagnostic category, provider name, and a redacted structural example if possible; never include a private subscription URL or raw calendar payload.

Earlier native subscription QA for the committed ICS fixes passed in Obsidian 1.14.5 on macOS using a dedicated test Vault and the then-final ZIP. It verified a public Google Taiwan holiday feed, rapid URL/Enabled changes, URL clearing and blank-source behavior, a controlled UTF-8 BOM feed with a zero-duration and normal event, and sanitized Settings status/cache retention after an injected HTML response. The main-calendar failure banner was not inspected natively and its visibility has source and unit-test coverage only. The current parser compatibility and diagnostics changes described above have not yet received test or native QA results. The user's exact feed remains unverified because its URL was not provided.

## Automated checks and controlled feed testing

Run `npm run typecheck` and `npm test` before packaging. Tests cover date/week rules, provider setting resolution, note/path handling, ICS parsing, subscription refresh behavior, source reconciliation/history, and storage recovery. They run against test adapters and fixtures; they do not prove behavior in an installed Obsidian app.

For controlled subscription testing, use a private local HTTPS fixture server or an HTTPS test endpoint that you control. Add its URL as a source in the test Vault, and use deterministic ICS fixture revisions for baseline, changed time, unchanged revision metadata, cancellation, recurrence override, invalid feed, and recovery cases. Avoid putting real calendar URLs or payloads in repository fixtures. Confirm manual Refresh and scheduled refresh, conditional fetch/cache retention, recurrence expansion, all-day exclusive end dates, time zones/DST, and independent behavior when one source fails. For source-change tests, compare the event view, managed Event Note fields, the exact tracked Daily Note bullet, unrelated journal content, and History before and after. Test local override resolution, Retry eligibility, source supersession, changed or ambiguous recurrence identity, and interrupted write recovery.

## Native Obsidian test-Vault checklist

Native QA was completed for the scenarios below in an isolated Vault with Obsidian 1.14.5. The build was copied into the Vault as `main.js`, `manifest.json`, and `styles.css`; the plugin loaded, registered its commands, and opened the Calendar-Note view. This does not establish every acceptance criterion.

Verified in Obsidian 1.14.5:

- Creating a local event created its Event Note and Daily Note bullet immediately. With core Daily Notes enabled and its folder setting blank, the Daily Note was created at the Vault root as `YYYY-MM-DD.md`.
- Rescheduling a local event across days preserved custom YAML properties and note body, retained the past-date journal, and moved only the tracked event link to the new date's Daily Note.
- Clicking an empty main-calendar date header opened that date's native Daily Note without creating an Event Note.
- A controlled subscription test passed an ICS feed into the actual parser and source-sync path. Changing an event from the 23rd to the 24th retained its Event Note path and body and moved its Daily Note link.
- Injecting a Daily Note write failure during a change from the 24th to the 25th rolled back the note/cache update and persisted a pending review row.
- After plugin reload, the pending 24th-to-25th change remained available. Retrying reused the same history ID, applied the new time and moved the Daily Note link; marking the row reviewed persisted.
- Native editor QA opened `Weekly Notes/2026-W43.md`, and typed content autosaved. With no user template, the note contained `## Weekly review` and no generated H1. A final reload preserved the edited Weekly Note text and reviewed state.
- A live `requestUrl` request to the public `https://raw.githubusercontent.com/kewisch/ical.js/master/samples/minimal.ics` fixture parsed one event and its `VTIMEZONE`. The event was unlinked, so the Vault file count remained unchanged; the source was disabled after the check.
- Imported Event Note renames through Obsidian's file manager passed both with automatic internal-link updates enabled and with the “Do not update” prompt choice. Each left one valid managed Daily Note bullet, removed the old bullet, cleared pending rename state, retained the stable event ID and new path, and preserved Event Note body and unrelated journal text. Saved state agreed, and no recovery journal remained. A second reload preserved links, `reviewedAt`, source-times resolution history, and native-edited Weekly Note text.
- Native UI inspection confirmed the Month/Year date control is a single clickable date with no overlap, Week labels are single-line English abbreviations with no redundant week row, and the full-width event-title field is focused and defaults to today.
- Calendar opening QA confirmed both commands create fresh leaves and keep the active Event Note open: `open-calendar` opens a new tab, and `open-calendar-right` opens a separate right split beside the note. A plain ribbon click opens a fresh tab in its group; Cmd-click opens a right split. Both commands are available for user-assigned hotkeys and have no default bindings. Native testing exercised Cmd-click on macOS; Ctrl-click is covered by the platform-independent modifier logic tests.
- Event Note Properties behavior passed in source and reading modes: Collapsed applies when an Event Note opens, a manual toggle to expanded remains in effect after 450 ms, reopening the same Event Note reapplies Collapsed, and ordinary notes remain expanded. Expanded also remains selected after reopening; Follow Obsidian preserves the native state without adding Properties observers. A same-path note without a nonblank `event_id` is treated as ordinary even if the plugin previously recorded its path as an Event Note.
- A fresh Event Note whose basename matches its event title contains only `event_id`, `start`, and `end` frontmatter, with no generated H1 or extra body headings.
- The `remove-duplicate-event-note-title` command removed a leading H1 exactly matching the active recognized Event Note's basename while preserving frontmatter (including its owner property) and the remaining body. Running it again left the file byte-for-byte unchanged. Recognition requires a nonblank `event_id` and valid start/end interval; it was unavailable on an ordinary same-path note without `event_id`.

Source-resolution QA confirmed that a local override remains effective when the source baseline changes; **Use latest source times** clears the override, applies the accepted interval, moves the managed Daily Note bullet, preserves Event Note body, and records a separate resolution-history row. An identical source snapshot caused no revision increment, history row, or linked-note write. Editing Event Note frontmatter directly retained event identity, established a local override, and a rescan moved the managed Daily Note bullet while preserving custom YAML and body. A controlled Daily Note write failure rolled back note/cache changes and persisted a review row; after reload, retry reused the same history ID and applied the new time, and marking it reviewed persisted. A controlled 23rd-to-24th source change retained the Event Note path/body and moved its Daily Note bullet.

The automated suite and `npm run typecheck` are the repeatable checks for the current source. The legacy browser-preview suite passes all five test files with the preview-local CommonJS package scope. Automated checks and library-level callback tests do not establish native drag behavior or narrow-window layout.

Native UI checks confirmed the sidebar and main calendar fill available height and bottom-align with mini-calendar content; centered English date labels remain single-line without duplicates through All days → Workdays → All days and Week → Month → Week; pointer and keyboard resizing work; and sidebar width, collapsed state, Workdays setting, and Week view persisted through reload. The mini-calendar kept all seven days. The final × close control and compact, keyboard-focusable left-edge restore handle passed native interaction checks; restoring returned the sidebar at its saved 264 px width without a toolbar control. Month/Year controls, event-title focus/default, rename behavior, Weekly Note text, and review/resolution state also passed native checks.

Remaining native verification: activate the highlighted week-number entry point; verify narrow-window overlay behavior and deeper Year/List layouts; exercise imported event provider precedence and equivalent instants with different timezone offsets in the native app; and drag/move events and both resize edges. Offset equivalence has automated regression coverage but no separate native retest.

The source and automated checks do not count as native-app QA. Continue with the remaining scenarios in a disposable test Vault:

- Install from the ZIP and from the explicit test installer; enable, reload, disable, and re-enable the plugin.
- Open the view and all six views; navigate weeks/dates; use mouse and keyboard entry points; create, overlap, move, resize, and edit events. Confirm the title field is focused, defaults to today, and uses a vertically labeled full-width row.
- With no subscriptions, create local Event Notes, open Daily and Weekly Notes, edit them in Obsidian, reopen/reload, and verify existing Markdown, frontmatter, paths, and managed bullets remain intact. Verify the compact left-edge restore handle, then verify narrow-window overlay behavior and deeper Year/List layouts. Confirm only the main calendar hides weekends and the mini-calendar/week rules remain unchanged.
- Click the highlighted current-week gutter number and other week numbers to open Weekly Notes. Check core Daily Notes, Calendar, and Periodic Notes provider precedence, fallback behavior, templates, locale, Sunday/Monday starts, calendar versus ISO week identity, and dates around New Year.
- With controlled HTTPS fixtures, test normal refresh, failure/cache retention, recurrence and exceptions, time zones/DST, cancellation/removal, local overrides, history filters/review/retry, and use-latest resolution.
- Cause safe path conflicts, rewrite or move a managed journal bullet, and simulate restart/interrupted recovery in a disposable Vault. Confirm user text is preserved, unsafe changes require attention, and successful recovery does not duplicate history or links.
- Inspect plugin unload/reload and app restart for timers, stale views, and pending recovery behavior.

Record additional Obsidian version, OS, test Vault description, fixture IDs (never private URLs), and pass/fail notes here as QA continues. Native behavior outside the verified scenarios above remains unverified.

Known display behavior and constraints: Calendar-Note uses English abbreviated labels for calendar chrome regardless of note locale, with main date headers kept on one line (for example, `Sun 18`). The sidebar mini-calendar can show adjacent months when the available height permits. Moment locale and week rules still control date formatting and week identity.

New-note heading behavior: the no-template Daily Note fallback begins with `## Journal`, and the Weekly Note fallback begins with `## Weekly review`, without generated H1 headings. A new Event Note omits a title heading when its actual basename matches the original event title; otherwise it starts with an H1 containing the original title. Without a user template, its body has no automatically added `Notes` or `Follow-up` sections. The `Calendar-Note: Remove duplicate Event Note title` command is available only for an active recognized Event Note and removes only a leading H1 that exactly matches its basename. It preserves frontmatter and all remaining body text. Existing notes and user-provided templates are preserved; the command is opt-in and there is no automatic mass migration.

## Browser prototype

The preview directory has its own CommonJS package scope so its legacy UMD scripts and tests remain CommonJS while the plugin project uses ESM. Run `node --test docs/changes/calendar-note/preview/*.test.cjs docs/changes/calendar-note/preview/smoke-test.cjs` to run the five legacy preview test files. To view the older browser-only prototype, run `python3 -m http.server 4318` from the repository root and open `http://127.0.0.1:4318/docs/changes/calendar-note/preview/index.html`. Its controls demonstrate interaction design using local browser storage and sample data. They do not exercise Vault writes or network subscriptions.
